## 本地运行

需要 Python 3.12 及锁定的 `blake3==1.0.9`。在独立环境安装依赖；不使用或导入 Ingest 内部模块。

```sh
PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -v
PYTHONPATH=src .venv/bin/python -m muli_sorter.cli \
  --staging /path/to/staging \
  --projects /path/to/projects \
  --runtime-snapshot /path/to/recent-status.json \
  --output /path/to/separate-local-output
```

输出必须在中转与项目目录之外；指向输入的软链接别名也会被拒绝。原型要求 Ingest 开启 JSON 清单；只有 Markdown 的批次会关闭处理并提示，不猜测转换。

运行状态文件结构：

```json
{
  "generated_at": "2026-09-28T00:00:00+00:00",
  "batches": [
    {"batch_id": "BATCH_20260928_000001", "batch_uid": "example-uid", "revision": 1, "state": "COMPLETED", "result": "COPY_VERIFIED", "completed_at": "2026-09-27T23:59:00+00:00"}
  ]
}
```

以上是合成示例，不能用于真实批次。状态快照必须在 120 秒内、与回执同批同版本一致。本轮真实验证由主代理通过已有可信 SSH 只读查询最小状态生成快照，不读取凭据；原型不携带数据库或凭据。只读状态适配和独立服务入口已完成，见下文 0.5；0.5 已通过 NAS 持续服务验收；一次 SSH 快照仍不能替代持续服务验收。

设备经常互换，采用每场拍摄确认，不保存固定设备—人员映射。可选 `--bindings` 接受 `{"bindings": [...]}`。每个对应关系要求 `manifest_id`（精确批次/清单版本）、`source_id`、`project_id`（预览中的内部目录标识）、带时区的 `start`/`end`、`confirmed: true`、`confirmation_reference`。确认不会继承到下一批或新版清单。规则是实际人工确认记录的输入，不能由 AI 自行写 confirmed。当前并未登记任何真实拍摄对应关系。

## 确认页和计划

生成器输出 `分类预览.html`、`分类预览.json`、`拍摄段确认.html` 和 `确认模型.json`。打开确认页，按实际拍摄段选择项目，再点击「确认归属」。下拉框选择本身不算确认；合并、拆分后需重新确认；RAW/JPG 等成组素材不能拆开。

```sh
PYTHONPATH=src .venv/bin/python -m muli_sorter.check_plan \

```

结果只打印到标准输出，始终包含 `executable: false`、`media_write_authorized: false`。浏览器只输出单元和项目 ID；目标项目路径从确认模型取得，不接受浏览器附加目标路径。所有单元必须出现一次，未处理和暂缓项也不能省略。模型内容摘要用于发现快照错配或内容变化，不是身份签名，不能把任意来源的模型当作可信执行依据。

合成演示与真实清单分开，浏览器验收只对合成示例选择项目和下载计划。真实 LRF 样本仍全部待确认。

## 合成归档实验

仅 macOS/Linux，Python 3.12，POSIX 目录句柄与文件锁。以下命令在**不存在的本地目录**生成小型合成 JPEG、H.264 MP4、伴随文件、成功清单和示例确认计划，然后执行复制与重复运行核验。生成资产已经打包，不要求用户安装 FFmpeg。实验入口拒绝 `/Volumes/` 和真实标识的批次/模型；标记文件是避免误操作的保护，不是对恶意本机进程的安全沙箱。

```sh
PYTHONPATH=src .venv/bin/python -m muli_sorter.archive_demo --output /path/to/new-local-demo
```

也可使用 `--prepare-only` 先生成实验目录，在其 `拍摄段确认.html` 确认合成项目并下载计划，再继续：

```sh
PYTHONPATH=src .venv/bin/python -m muli_sorter.archive_demo \
  --workspace /path/to/existing-local-demo \
  --decisions /path/to/downloaded-synthetic-plan.json
```

运行回读完成清单、120 秒内的模拟运行快照、拍摄元数据和精确文件清单，再独立复制。照片进入现有项目的 `1相机原素材/独立归档/单元ID/原始相对路径`；视频进入 `2视频素材/未指定机位/独立归档/...`，不会猜相机/侧拍角色。这只是合成目录方案，正式项目路径还需确认。

每个单元先把全部文件复制到目标目录的隐藏临时文件并校验，再逐文件独占发布；**多文件发布不是一次原子事务**。中断可能留下部分正式文件，只有全部文件回读通过且生成单元回执，才显示单元完成。恢复先核验已发布文件和临时前缀，再续传。未登记文件、损坏临时文件、源改变和目标冲突保持未完成，保留现场，不自动覆盖或清理。极短的“临时文件已创建但身份记录尚未落盘”窗口会保守停止，需人工核对，不承诺任意断电点均能无人干预恢复。

目标是新建独立副本。内部只使用新副本临时名到正式名的硬链接进行禁止覆盖发布，随后去掉临时名；从不把源文件硬链接到项目。中转源文件保持原位，目标内容变更不应影响源。状态记录、单元回执和 `latest-run.json` 位于实验目录 `state/`；索引可从持久任务意图恢复。回执是当时验证结果，再运行仍重新核对源与目标，不把旧回执当成永久完整性证明。

测试包括真实子进程在任务意图写出、复制中、文件发布后和回执写出后退出，再由新执行恢复；这不等同于 NAS 物理断电、文件系统故障或长期服务验收。当前强调完整性和恢复，完整内容读回有额外 I/O，尚未做大文件吞吐与并发优化。运行状态提供方在测试中是合成快照，尚未接通生产的实时只读接口。普通 `classification_confirmation_only` 计划仍不授予真实写入权限。


## 只读发现队列 0.4

`muli-sorter-queue` 每轮采集最小批次状态，在分类自己的 SQLite 中保存进度；没有导入 Ingest、写其数据库或更改原片的代码入口。完成门槛保持精准内容校验、成功回执、两份清单摘要、同批同版本最终状态全部一致。仅数量/大小校验的结果单列为需要精准校验证据。

生产格式状态可从已获授权的本地只读数据库挂载，或已有可信 SSH 别名读取。当前 Ingest 没有增量完成 API，使用 `objects(kind='batch')` 中 JSON 的六个投影字段；不会读取文件明细表或设置/认证记录。适配器依赖当前内部表结构，结构变化会停止读取而非猜测。数据库以 `mode=ro`、`query_only=ON` 打开；不可使用 `immutable` 绕过活动 WAL。未完成批次的 revision=0 被正常保留等待。

```sh
PYTHONPATH=src .venv/bin/python -m muli_sorter.queue_cli \
  --staging /path/to/staging --projects /path/to/projects \
  --state-db /path/to/readonly-ingest-state/ingest.sqlite3 \
  --output /path/to/separate-local-sorter-state --cycles 1
```

远程只读状态改用 `--ssh-host 已核验别名 --remote-db /absolute/path/ingest.sqlite3`，中转和项目目录仍须在本机通过已挂载只读路径可见。仅使用已有 SSH 登录能力，强制 BatchMode 与已有主机指纹核验；不读取凭据、不自动接受新主机、不绕过登录失败。不把 SSH 轮询等同于已部署的 NAS 服务。

默认仅观察一轮，每轮最多准备一批。显式 `--cycles 0` 才持续运行；`--interval 2` 表示每轮工作结束后再等 2 秒。长清单整理仍会延长下一次观察间隔，因此当前版本不承诺压力下固定 1–5 秒发现。生产性能阶段需将轻量发现和较重的分组工作分开调度。

可用 `--snapshot` 读取新鲜完整快照；必须包含 `complete_listing: true`，否则暂停。配合 `--synthetic` 只接收明确的合成批次。状态失效不伪造新时间，离线会显示状态不可用，已持久任务保留。失败重试从 2 秒退避至最多 60 秒；恢复后通过完整列表补回未观察到的批次，不只依靠事件通知。最多读取 10,000 批，超出后停止并提示分页适配，不截断成成功列表。

正常轮询读取小型回执和清单文件属性；新批次、证据变化或任务恢复时才完整验证清单并整理。任务键绑定批次身份、清单版本和规则版本；新版本使旧记录停用，项目索引约每 60 秒刷新一次，变化会重建未执行计划。没有自动迁移人工归属决定。已经发布的模型在重启及文件属性变化时校验内容，丢失输出可重建。异常退出后的处理中任务重新排队，成套确认文件写好之后才标为待确认。

只读页面将多个完成批次合并为一份确认模型，重复来源文件合并为一个不可拆素材单元。目录/时间相符仍只是候选，程序不会据此选择真实项目。输出含 `分类队列.html`、`队列状态.json`、稳定模型标识下的合并确认页和分类自己的 `queue.sqlite3`；不得放在 Ingest 状态、中转或项目目录内。旧快照仍是历史资料，不能替代执行前的新鲜验证。进程停止时页面明确显示观察已结束。

本轮完成 5 轮真实只读观察及重启复用，未保持后台进程、安装定时任务、部署容器、打开端口或触发模型。真实待确认页覆盖 3 个已完成批次，跨批去重后 292 个文件、148 个素材单元、22 段候选拍摄；另 2 批仍在拷贝。这些是采集时刻的状态。


## 常驻服务与订单接入 0.5

`muli-sorter-service` 使用父进程负责观察和队列数据库，spawn 子进程负责较重的清单验证、分组。慢分组期间，新完成的批次仍可先入队。父进程中的项目索引刷新、状态读取及页面汇总仍可能消耗时间，2 秒是目标轮询间隔，不是生产延迟保证。停止与重启不会清除任务；处理中任务在下次启动重新核验。

容器配置在 `deploy/`，用于 linux/amd64 的 NAS：输入均只读，输出目录独立可写，无网络、端口或 Docker socket，以 1000:1001 运行，0.5 CPU / 512 MiB。网络隔离的分类容器不负责访问飞书；订单读取作为独立适配步骤接入，不能因为分类容器运行就宣称飞书无人值守已接通。

订单适配器 `order_catalog.read_orders(resource, dates)` 使用既有已登录 `lark-cli`：以明确拍摄日期筛选，仅读销售编号、预约拍摄时间、客户姓名、订单环节、关联套餐及目录字段。所有分页必须完整、表版本一致；输出保留订单记录 ID、读取时间和拍摄日期。一次最多 60 个日期、4,000 条记录，超限明确停止，不把截断结果当完整。可分批处理更长历史；不按拷贝日期或固定最近天数过滤。

`order_projects.plan_folders` 先按销售编号查已有目录。唯一且日期一致时复用；无目录时调用现有建目录服务的纯命名函数（通过 `folder_namer` 注入）生成待建意图；重复目录、取消退款、缺少关联套餐、无效套餐代码或日期不一致转核对。它不调用建目录 API、不改飞书、不建真实目录。

`enrich_confirmation` 将这些证据加入确认模型，缺目录项目显式显示“待建目录”。所有素材归属仍保持待确认，模型变更产生新报告 ID，旧草稿不能静默套用。确认归属后，生产执行器应重新读订单与目录，创建或复用标准目录，回读成功后才归档。该生产执行器尚未实现；普通确认计划仍为 `executable=false`。
