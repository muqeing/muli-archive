# 当前清单的文件统计

归档状态使用同一份正式清单作为统计范围。每个来源路径只计一次；一个素材单元可包含多个文件。表内六类互斥，素材列和文件列各自合计，不将两个单位混加。

| 去向 | 判断依据 |
| --- | --- |
| 已归档 | 原历史投影已核对且在当前清单中的素材；文件数须与原回执数量一致 |
| 旧任务来源保留 | 原有未完整内容核验投影，独立于已归档，保留原禁删条件 |
| 待归档 | 既未归档也不属于来源保留的主素材或已识别附属素材 |
| 待核对 | 异常、未知或缺失类别；不能凭路径缺失推断已归档 |
| 系统辅助 | 原素材核对规则已经识别为support的文件；无需项目选择 |
| 已弃用 | 原可恢复弃用投影；不计作已归档，不删除文件 |

例如，一个MP4与LRF组成一个素材，另一个素材含两个THM/SCR文件，两者归档完成后是2个素材、4个文件。附属文件已包含在4个文件中，不能再加一次。格式分解只解释文件数量；XML、LRF等扩展名不证明与某个主文件对应，也不改变原关联和归档门槛。

全部历史素材记录按现有历史目录的最新素材记录统计，跨清单、按需分页。它不代表当前清单中的文件数，也不表示实际执行次数。

统计由页面生成时已加载的当前正式清单、素材状态和原历史投影一次计算，随原页面缓存保存。不会为了汇总再次读取旧清单、遍历项目媒体或计算文件摘要。重新检查来源会使旧统计失效；用户保存草稿并重新加载后获取新的完整统计。缺失或矛盾的统计不会伪造零差额、不会阻断控制台显示，也不会触发预检、提交、重试、移动、删除或补发完成记录。

系统文件仍采用既有严格识别规则。不认识的BIN/DB文件继续待核对；真实拍摄附属文件不通过改称系统文件从完成分母中消失。本版本没有改写Ingest清单或历史完成口径。旧版本的部分完成反馈与来源保留不能仅靠界面统计转为完成。
