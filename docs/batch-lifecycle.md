# 批次结案与历史读取（0.17.0，显式启用）

源码功能已提供，已有 NAS 镜像不会因更新 GitHub 自动启用。上线、停服迁移与生产验收须分别执行。本版本不删除任何历史记录或素材。

## 工作规则

- 拷贝完成不等于归档完成。分类服务只接受 Ingest 已验证、未过期、完整覆盖本批次当前 revision 的归档反馈摘要来结案。
- `closed` 退出分类轮询、候选刷新和合并模型；同一身份/版本重启后不复活。原清单、来源依赖和回执继续保留。新 revision 是新工作。
- 部分归档、过期反馈、范围冲突及未完成内容校验不自动结案。同一已结案版本的拷贝完成状态倒退，转独立 `needs_attention`，不悄悄重新执行。
- `cancelled` 仅取消分类和发布后续分类结果；不取消归档执行器，不回滚已移动文件，不删除媒体。
- 结案是历史工作流事实，不是新的目标健康证明、清理许可或相机卡格式化许可。原反馈工作器的短期校验与清理凭据机制保持。

## 启用方式

分类服务命令追加 `--enable-batch-lifecycle`。它仍读取完整的**最小批次摘要**，供 `existing_copy` 等旧来源依赖解析；退出的是旧模型和媒体检查，不截断来源列表。源库只读，仅队列自己的库持久保存结案/取消。

归档服务可以分别启用：

- `--indexed-reservations`：一次性事务迁移 `reservations.json`，之后精确查询本次 source 与候选目标。旧 JSON 冻结保留；数据库损坏、身份不符或旧 JSON 被修改均停止，不降级到过时数据。
- `--indexed-history`：只按当前单元/内容指纹定位相关原回执；历史用 SQL 分页、默认 50 条。派生目录负责定位，当前素材仍走原有回执、范围及移动闭合验证。单个指纹从重复摄入记录选取一个最新来源；其证明失败则保留待处理，不用旧目录冒充验证。

历史目录须先显式离线构建：在确认所有生产任务空闲、停止归档服务并保存回退快照后，使用归档控制台原参数，追加 `--indexed-history --build-history-catalog`。此操作在已有服务独占锁下创建派生目录、打印迁移结果并退出，不启动归档 worker。报告会单列原有异常任务及未核验来源保留任务，不把它们算成已验证归档。

普通启动不会隐式展开全部旧回执。正常控制记录发布后增量刷新变动任务；控制目录变化时仍需枚举任务文件的元数据。最近任务最多保留 20 份摘要。历史目录启动时进行流式结构一致性检查；首次迁移和冷启动验证可能较慢，并非恒定时间承诺。

## 管理 CLI

这些命令是分类状态管理入口；远程 `muli-archive` 的提交接口和写入确认要求保持。

```sh
# 可在分类服务运行时只读分页查询，数据库 query_only，不迁移、不复活任务。
muli-sorter-queue --staging /staging --projects /projects --output /sorter-state \
  --enable-batch-lifecycle --history --offset 0 --limit 50

# 先停止分类服务以释放单实例锁；只取消指定分类 job。
muli-sorter-queue --staging /staging --projects /projects --output /sorter-state \
  --enable-batch-lifecycle --cancel-job JOB_ID --confirm-cancel
```

没有取消确认会拒绝操作；不能绕过现有服务锁。分类状态不提供媒体删除接口。

## 回退

1. 初次迁移前保存归档/分类自有状态与配置快照，保留旧镜像。不得删除业务记录或共用锁。
2. 历史目录是派生状态，可以停服后移开新目录，回退到旧历史读取路径；原回执、原请求不变。
3. 预留 SQLite 启用后可能包含旧 JSON 没有的新任务，禁止直接切回旧 JSON。先停服并导出完整、逐份摘要回读的新快照：

   ```sh
   muli-sorter-reservations-export --state /archive-state \
     --filename reservations-rollback-REVIEW_ID.json --confirmed
   ```

   导出在服务独占锁下流式写入一个**新文件**，不替换旧 JSON、不停服、不切镜像。只有核对导出条目、原任务和恢复范围并获得实际回退授权后，才能安装回退快照。结果未知先回读，不盲重放。
4. 已持久结案的分类库禁止直接关闭生命周期开关来复活旧批次。只有期间未产生新工作的前置快照可按已核对范围恢复；否则保留结案事实做兼容修复。

## 保留策略与验证范围

尚未启用自动过期删除。7/30/90 天只是后续清理方案；需要先解决活跃引用、旧 `existing_copy` 依赖、结果未知的任务和最小资产凭证，再生成具体清理预览。正式项目、未归档中转文件、内容未完整核验的来源不在本版本的删除范围。

本地合成检查覆盖结案/取消/新版本、完整/部分反馈、索引事务、大小写及 Unicode 冲突、历史分页、重复内容定位、原提交中断恢复、直接移动、受保护来源保留、外部回执变化。10/100/1000 历史条目的固定当前查询可用于验证返回范围及 Python 分配上限；它不代表 NAS RSS、整站加载、长期驻留内存或真实媒体性能通过。短期反馈续验、最小摘要枚举和后台控制元数据枚举仍有成本，应在生产验收中单独测量。

## 2026-10-17 上线只读验收

NAS已完成显式迁移和启用、安装摘要及电脑/手机/分页/只读CLI验收。维护源码798项、NAS归档452/分类54项相关检查通过且无skip。启动验证按既有索引流式选取最新记录，避免完整JSON窗口排序撑满小tmpfs；媒体token排除独立续期的工作流反馈字段。页面允许当前内容重复项数大于历史原始条目数。显示可使用全部原依赖inode/大小/mtime/ctime未变的旧投影；任何依赖变化回退相关原回执，执行范围不使用该显示快捷路径。

初始失败、回退和冷启动超时均保留。没有真实新归档或自动删除验收，没有启用历史保留期限；未完成批次及原媒体仍保持。长期内存趋势尚未验收，文件缓存可占据资源限额，不能与程序匿名内存混为同一泄漏证据。
